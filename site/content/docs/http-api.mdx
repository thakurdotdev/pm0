pm0 exposes an HTTP API for tooling: dashboards, CI/CD hooks, health
probes. It streams the same information the CLI shows, as REST plus
server-sent events for logs.

<Callout type="warn" title="Opt-in and off by default">
  The HTTP API is **disabled unless you enable it explicitly**. There is **no
  built-in authentication**. The listener binds to loopback or a Unix socket
  only — your backend terminates authentication. Never expose the port
  publicly.
</Callout>

## Enabling the API

Three ways, in increasing order of permanence:

1. **Environment variable** — start (or restart) the daemon with:

   ```bash
   PM0_HTTP_ADDR=127.0.0.1:9615 pm0 resurrect
   ```

2. **Daemon flag**:

   ```bash
   pm0 daemon --http-addr 127.0.0.1:9615
   ```

3. **Installer prompt / config file** — the installer offers to enable the API
   and writes the address to `$PM0_HOME/config`:

   ```bash
   # $PM0_HOME/config
   http_addr = 127.0.0.1:9615
   ```

**Default port: 9615** (mirrors PM2's convention). Bind to a Unix socket
instead of TCP by pointing the address at a socket path.

## Endpoints

### List processes

```bash
curl -s http://127.0.0.1:9615/api/v1/processes | jq
```

Returns the same JSON shape as `pm0 jlist`: name, id, mode, pid, uptime,
restarts, status, cpu, mem per process.

### Restart a process

```bash
curl -s -X POST http://127.0.0.1:9615/api/v1/processes/api/restart
```

Triggers the same restart path as the CLI: SIGINT → kill_timeout → SIGKILL
through the actor mailbox.

### Stream logs (SSE)

```bash
curl -N http://127.0.0.1:9615/api/v1/processes/api/logs
```

Server-sent events, one per log line, `event: stdout` / `event: stderr` with
the payload in `data:`. The stream follows the live ring buffer.

## Security model

The design assumes the API is consumed on the same machine:

- **No built-in auth** — no tokens, no TLS. The address space *is* the auth
  boundary.
- **Loopback / Unix-socket only** — `127.0.0.1`, `::1`, or a Unix socket path.
  Binding to a public interface is rejected by the daemon.
- **Your backend terminates auth** — put a small proxy (nginx, Caddy, your
  app) in front if you need remote access, and enforce authentication there.
