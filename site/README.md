# pm0 website

Marketing site + documentation for [pm0](https://github.com/thakurdotdev/pm0) —
a PM2-compatible process manager written in Go.

Stack: **Next.js 16 (App Router)** · **Tailwind CSS v4** (CSS-first tokens) ·
**Fumadocs 16** (MDX docs + ⌘K search) · **shadcn/ui** · **next-themes**
(dark default) · Geist fonts.

## Quick start

```bash
bun install
bun run dev        # http://localhost:3000
```

Production (standalone output):

```bash
bun run build      # next build + copies static/public into .next/standalone
bun run start      # serves the standalone build on :3000
```

## Design system

- **Tokens live in `src/app/globals.css`** (`@theme inline` + `:root/.dark`
  and `.light` blocks). Dark is the default theme; no hardcoded hex in
  components — everything goes through semantic tokens
  (`surface/elevated/line/ink*/accent/code-*`).
- **Code surfaces are always dark in both themes** (`--code-bg`,
  `--code-ink*`); Shiki emits dual themes and `globals.css` forces the dark
  palette.
- Red (`--accent`) is reserved for the logo, primary CTA, `$` prompt and
  status dots.
- Typography scale classes: `.heading-hero`, `.heading-display`,
  `.heading-h2`, `.heading-h3`, `.label-caption`.

## Data & single source of truth

- The **version string lives only in `src/lib/github.ts`**
  (`FALLBACK_VERSION`, used when the GitHub API is rate-limited/unreachable).
  Nav badge, hero pill, footer, changelog and install snippets all consume it.
- Release/repo data is fetched through `unstable_cache` (1 h revalidate).
  Set an optional `GITHUB_TOKEN` env var to raise GitHub API rate limits in
  production.
- `/changelog` renders GitHub releases with a graceful fallback card.
