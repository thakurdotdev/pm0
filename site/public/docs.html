pm0 Reference Guide

Everything you need to install, configure, and operate pm0 in development and high-load production environments.

Installation & The Short Path

Install pm0 with a single shell command and deploy your first high-throughput supervised cluster in under 60 seconds.

01

Download & Install

Automatically detects your CPU architecture (amd64 / arm64 / arm / 386) and downloads the static Go binary with zero external dependencies.

$ curl -fsSL https://pm0.thakur.dev/install.sh | bash
Ensure ~/.local/bin is in your $PATH:
export PATH="$HOME/.local/bin:$PATH"
02

Launch Supervised Processes

Start your server in cluster mode. Workers share ports via Linux kernel SO_REUSEPORT socket pooling.

$ pm0 start server.js -i max
03

Inspect Health & Dynamic Scaling

View your live status table with sub-40ms CLI execution. Adjust worker pool counts on the fly without restarts.

$ pm0 status && pm0 scale web +2
04

Zero-Downtime Rolling Reload

Deploy updates seamlessly with zero dropped packets and zero 502 Bad Gateway errors.

$ pm0 reload web

Quick Start

Starting Applications

Pass your application entry file. pm0 inspects file extensions and shebangs to select the appropriate interpreter automatically:

bash 
# Node.js fork mode
$ pm0 start server.js --name web

# Cluster mode: 1 worker per CPU core, sharing one port
$ pm0 start server.js -i max

# Bun & Deno runtime targets
$ pm0 start server.ts --interpreter bun --name bun-api
$ pm0 start server.ts --interpreter deno --name deno-api

# Python (auto-detects python3)
$ pm0 start app.py --name python-app

# Compiled native binaries (Go, Rust, C++)
$ pm0 start ./my-binary --interpreter none --name go-service

Inspecting & Managing

bash 
$ pm0 status                     # Instant process status table
$ pm0 logs web --lines 100       # Stream live logs with backlog
$ pm0 describe web               # View uptime, RSS, and cgroup limits
$ pm0 scale web +2               # Dynamically scale workers
$ pm0 reload web                 # Zero-downtime rolling reload
$ pm0 restart web | pm0 stop web | pm0 delete web

Zero-Downtime Cluster Mode

Cluster mode allows Node.js applications to share a single TCP listening port across all CPU cores. pm0 leverages Linux kernel SO_REUSEPORT socket sharing (available in Node.js ≥ 23.2, Linux kernel ≥ 3.9).

When rolling updates with pm0 reload <name>, new workers are spawned and verified healthy before the old worker is sent a graceful drain signal. This eliminates dropped packets and 502 Bad Gatewa

Ecosystem File (ecosystem.config.js)

pm0 is 100% compatible with existing PM2 ecosystem.config.js files. You can drop in pm0 without changing your CI/CD configuration:

ecosystem.config.js 
module.exports = {
  apps: [
    {
      name: "api",
      script: "./server.ts",
      interpreter: "bun",
      instances: 2,
      env: {
        PORT: 3000
      },
      env_production: {
        PORT: 3000,
        NODE_ENV: "production"
      }
    },
    {
      name: "worker",
      script: "./worker.py",
      instances: 1
    }
  ]
};

Launch the ecosystem file:

bash 
# Start all applications in the config
$ pm0 start ecosystem.config.js

# Start only a targeted app definition
$ pm0 start ecosystem.config.js --only api

# Apply production environment overrides
$ pm0 start ecosystem.config.js --env production

Systemd Auto-Boot Persistence

Preserve your application state across server reboots. Snapshot the active process table:

bash 
$ pm0 save

Generate and register the systemd service unit with root privileges:

bash 
$ sudo pm0 startup

pm0 writes state to ~/.pm0/dump.json. Override the root directory by specifying the PM0_HOME environment variable.

System Requirements

  • Operating System: Linux (Ubuntu, Debian, Fedora, Arch, Alpine, RHEL)
  • Process Tracking: Linux cgroup v2 (with automatic fallback to process group IDs)
  • Cluster Socket Sharing: Node.js ≥ 23.2, Linux kernel ≥ 3.9
  • Fork Mode: Works out of the box with any executable binary or script

Frequently Asked Questions

How is pm0 so much faster than PM2?

PM2 is written in Node.js and requires spawning a complete V8 instance to parse commands, load hundreds of npm modules, and negotiate IPC. pm0 is compiled into a single static Go binary with direct Unix domain socket communication, reducing command execution time from ~250ms to ~38ms.

Does pm0 work with non-Node.js runtimes?

Yes! pm0 natively supervises Bun, Deno, Python, Go, Rust, Ruby, PHP, and shell scripts without external wrappers.

How can I build pm0 from source?

pm0 requires Go ≥ 1.26:

bash 
$ git clone https://github.com/thakurdotdev/pm0.git
$ cd pm0
$ make build
$ sudo make install
